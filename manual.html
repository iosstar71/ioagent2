ver1.0.9 주요 변경 사항

  • 주간보고 통합 다운로드: 주간보고 화면 상단의 [📥 엑셀 주간보고] [📥 워드 주간보고 (표 포함)] [📥 워드 주간보고 (표 제외)]는 목록에서 고른 주차에 작성 완료된 통합·서브시스템 주간보고를 모두 취합하여 1개 통합 보고서로 만듭니다. 선택한 보고서 1건만 나오지 않습니다.
  • 취합 규칙: 통합(PM) 보고서가 작성 완료되어 있으면 그 요약·현안을 먼저 싣고, 서브시스템 요약은 [서브시스템] 머리말을 붙여 이어 붙입니다. 금주 실적·차주 계획은 작성 완료된 서브시스템 보고서 항목을 서브시스템 순서대로 싣습니다. 보고서 첫 부분의 [주간보고 작성 현황]에 작성 완료·미작성 서브시스템이 표시됩니다.
  • 분야별 주간보고 제외: 목록과 작성 단위는 통합 / 서브시스템만 남겼습니다.
  • 워드 표 정리: 금주 실적 표의 머리글(7열)과 내용(6열)이 어긋나던 문제, 차주 계획 표의 열 너비 정의가 1열 모자라던 문제를 고쳤습니다. 표 머리글은 페이지가 넘어가도 반복됩니다.
  • 로고: 프로젝트 로고(일정 막대 + 마일스톤 마름모)를 상단 머리글, 로그인 화면, 브라우저 탭 아이콘, 매뉴얼에 표시합니다. 원본 파일: img/ax_pm_logo.svg
  • 명령 창 영어 표시: run_server.bat, run_tests.bat, build_standalone.bat 실행 시 명령 창에 나오는 안내·로그 문구를 모두 영어로 바꿨습니다.
RELEASE NOTE

ver1.0.8 주요 변경 사항

  • 접속 방식 안내: 서버 주소(http://서버IP:8080)로 접속했는데 로컬 저장소 모드이면 로그인 전에 서버 DB 모드 전환을 묻습니다. index.html 파일을 직접 열면 로컬 저장소 모드로 실행하며 서버 접속 방법을 안내합니다.
  • 서버 연결 감시: 서버 DB 모드에서 서버가 꺼지면 상단에 빨간 경고가 표시되고 저장이 막히며, 서버가 다시 켜지면 자동으로 풀립니다.
  • WBS 실적 자동반영: 100% 반영 시 계획완료일이 기준일과 같은 주차이면 계획완료일, 아니면 기준일을 실적완료일로 등록합니다. 실적시작일이 실적완료일보다 늦으면 실적완료일로 맞춥니다.
  • 지연 상태: 계획 진척률보다 실적이 1%p 이상 적으면 '지연'으로 저장되며, WBS 의 [상태 조회]에서 지연 최하위 Task 만 모아 볼 수 있습니다.
  • 간트차트: WBS 목록과 차트가 한 영역에서 함께 스크롤되어 행이 항상 맞춰집니다.
  • 주간보고: 주차를 고르면 그 주차의 통합·분야·서브시스템 보고서 목록이 나오며 미작성 단위는 [📝 생성]으로 만듭니다. [엑셀/워드 다운로드 (주차 통합 묶음)]은 목차와 함께 통합·분야별·서브시스템별 보고서를 한 파일로 만듭니다. 보고서 1건은 엑셀 셀 한도에 맞춰 32,000자 이내로 제한됩니다.
  • DB 연동: Oracle · Excel/Access 연동은 비활성화되었습니다. 서버 DB 는 SQLite 만 사용합니다.

  • 주간보고: 보고 주차별 목록(통합·서브시스템 작성 현황)에서 보고서를 선택하면 상세가 열립니다. 상단 [엑셀/워드 주간보고]는 그 주차의 작성 완료 보고서를 모두 취합합니다. 금주 실적·차주 계획 항목은 [✕] 제외, [WBS 과업 추가], [직접 입력 항목 추가]가 가능합니다.
  • 간트차트: 기준일 세로선 표시, 기준정보에서 등록한 통합/서브시스템 마일스톤을 ◆ 로 표시합니다.

  • 데이터 가져오기·내보내기: 주간보고·회의록·공지·소통 피드도 엑셀/JSON 으로 내려받고 올릴 수 있습니다. 총괄리더도 전체 업무 데이터를 올릴 수 있습니다.
  • 로그인: 로그인 화면에서 비밀번호 변경, 사용자 정보에서 사용자별 비밀번호 초기화(1234).

  • 표준화: DOCX → 워드 명칭, 엑셀·워드·JSON 다운로드/업로드 버튼 명칭과 버튼 색상을 기능별로 통일했습니다.

CHAPTER 01

1. 시스템 개요 및 아키텍처 (System Overview)

AX Project Management by YS ver1.0.9는 장비가동률 시스템 구축 및 기준정보관리 개선 등 엔터프라이즈 IT 프로젝트 수행 시 표준 SDLC 4단계(분석·설계·구현·테스트) 공정(WBS), 요구사항(REQ), 추가 VOC/이슈, 단계별 표준 산출물을 단일 웹 환경에서 통합 관리할 수 있도록 설계된 올인원(All-in-One) 프로젝트 관리 플랫폼입니다.

CHAPTER 02

2. 설치 및 환경 구성 가이드 (Installation Guide)

조직의 보안 정책(PC 폴더 공유 제한, 외부 클라우드 차단, 폐쇄망 운영 등)과 인프라 여건에 따라 아래 4가지 운영 모드 중 하나를 선택하여 즉시 도입할 수 있습니다.

모드 A. 서버 없는 단독 구동 + 로컬 JSON 협업 (권장·무설치)

  • 실행 방법: 압축 해제 후 index.html 또는 index.html을 Chrome/Edge에서 더블클릭합니다.
  • 데이터 보존: 브라우저 내장 IndexedDB에 자동 저장되며, 상단 협업병합 및 설정 2-2에서 로컬 .json 파일로 추출·스마트 병합합니다.
  • 장점: 서버 구축 비용 제로, 사내 PC 폴더 공유 보안 규정 완벽 준수.

모드 B. 사내망 간이 HTTP 웹서버 배포

  • 실행 방법: 패키지 폴더에서 python -m http.server 8080 또는 npx serve -p 8080 실행 후 http://사내IP:8080 접속.
  • HTTP 보안 호환: 순수 JS SHA-256 해시 알고리즘이 내장되어 HTTPS 인증서가 없는 사내 HTTP 환경에서도 사번·비밀번호 인증이 완벽 동작합니다.

모드 C. Node.js + SQLite / Excel·Access(ODBC) 연동

  • 실행 방법: server/ 폴더에서 npm install 후 node server.js 실행.
  • 설정 연결: 설정 → 2-1. 데이터베이스 연동에서 SQLITE 또는 EXCEL_ACCESS 선택 후 http://localhost:3000/api/wbs 적용.

모드 D. 엔터프라이즈 Oracle DB 연동

  • 실행 방법: server/schema.sql의 WBS_PROJECT_STORE 테이블을 Oracle DB에 생성 후 REST API 서버 기동.
  • 수동저장 권장: 다수 인원 접속 시 저장 방식을 수동저장(저장 버튼 클릭 시 반영)으로 지정하여 트랜잭션을 통제합니다.

2.2 파이썬 다중 사용자 DB 웹서버(wbs_db_server.py) 기동 가이드 및 실제 화면 예시

AX Project Management by YS ver1.0.9은 별도의 복잡한 웹서버(Apache, Nginx, Tomcat 등) 설치 없이, 파이썬 표준 라이브러리만으로 동작하는 경량 고성능 HTTP DB 웹서버(wbs_db_server.py)를 기본 제공합니다. 사내망 내 1대의 호스트 PC에서 기동하면 여러 팀원이 동시에 접속하여 SQLite 기반 실시간 협업을 수행할 수 있습니다.

🚀 서버 기동 단계 요약

  1. 간편 실행 (Windows): 패키지 루트의 run_server.bat를 마우스로 더블 클릭합니다. (포트 8080으로 자동 기동)
  2. 콘솔 수동 실행 (Windows / macOS / Linux): 터미널 또는 명령 프롬프트(CMD)에서 python wbs_db_server.py --port 8080 명령어를 입력합니다.
  3. 웹 브라우저 접속: Chrome, Edge 또는 Safari를 열고 http://localhost:8080 또는 사내 IP 주소(http://192.168.x.x:8080)로 접속합니다.

3.1 프로젝트 기준정보 및 ID 채번·인력 설정 (섹션 1)

설정 카드 상세 설정 방법 및 반영 범위
1-1. 프로젝트명 및 시스템 타이틀 • 시스템 타이틀(상단 로고 옆 메인 제목 및 브라우저 탭 타이틀)과 프로젝트명(상단 파란색 배지 및 엑셀/PPT 보고서 표지·헤더)을 자유롭게 정의합니다.
• 입력 후 타이틀/프로젝트명 적용 클릭 시 즉시 반영됩니다.
1-2. 프로젝트 일정·가중치·주차 시작요일 • 프로젝트 전체 시작일/종료일 및 공정 가중치(분석·설계·구현·테스트 합계 100%)를 설정합니다.
• 매주 시작 요일(예: 월요일, 일요일)을 변경하면 간트차트 주차별 표시의 1주차~N주차 시작일이 해당 요일 기준으로 즉시 재정렬됩니다.
1-3. 서브시스템 기준정보 및 약어 코드 • 서브시스템별 영문 약어 코드(예: EQP, MDM, MES, IF)와 명칭을 등록·수정합니다.
• 등록된 서브시스템은 전 탭의 조회 필터, 행별 서브시스템 선택 드롭다운, 그리고 ID 자동 채번에 즉시 연동됩니다.
1-4. 프로젝트 휴일/공휴일 캘린더 • 대한민국 공휴일(2025~2026) 기본 적재 버튼으로 공휴일을 일괄 등록하거나 임시 휴무일을 개별 추가합니다.
• WBS 계획일정 휴일 일괄 자동보정 클릭 시 휴일에 걸친 모든 과업 일정이 영업일로 자동 시프트됩니다.
1-5. WBS·REQ·VOC ID 채번 Prefix 및 서브시스템 연동 • WBS, 요구사항(REQ), VOC 각각의 기본 접두어(Prefix)와 서브시스템 약어 코드 결합 여부를 설정합니다.
• 예: 요구사항 Prefix REQ + 서브시스템 코드 연동 체크 시 → 장비가동률(EQP) 요구사항은 REQ-EQP-001로 자동 채번됩니다.
• 기존 데이터 ID 일괄 재적용 버튼을 누르면 기존 등록된 모든 항목의 ID가 새 규칙으로 일괄 업데이트됩니다.
1-6. 프로젝트 및 시스템 접근 인력 관리 • 사번(로그인 ID), 성명, 시스템 권한(ADMIN 관리자 / MEMBER 일반), 담당 서브시스템, 부서/직책, 초기 비밀번호를 등록합니다.
• 비밀번호 분실 시 관리자가 해당 행의 비번변경 버튼으로 즉시 초기화할 수 있습니다.
1-7. 단계별 표준 산출물 관리 • 분석·설계·구현·테스트 단계별 표준 산출물 양식과 1회차 제출 대상 / 2회차 제출 대상(복수 선택 가능)을 정의합니다.

3.2 저장소·DB 옵션 및 보안·초기화 관리 (섹션 2)

2-1. 자동저장(AUTO) vs 수동저장(MANUAL)

• 자동저장: 데이터 변경 즉시 로컬 IndexedDB 및 연결된 DB/파일에 반영됩니다.
• 수동저장: 변경 사항 발생 시 상단 메뉴에 주황색 저장 (N) 버튼이 활성화되며, 사용자가 버튼을 눌러야만 최종 저장됩니다.

2-4. 저장소 초기화 (JSON 보존 vs 전체 초기화)

• JSON 보존 초기화: 프로젝트 핵심 데이터(WBS·REQ·VOC·산출물 JSON)는 유지하고 UI 필터·세션 캐시만 초기화합니다.
• 전체 초기화: 모든 데이터를 삭제하고 초기 샘플 상태로 복원합니다.

  • WBS 계층 편집 및 접기/펴기:
    • 상단 서브시스템 조회로 담당 서브시스템만 필터링하고, 레벨 표시 드롭다운으로 1레벨(대분류) 또는 2레벨(중분류)까지만 접어서 볼 수 있습니다.
    • 각 과업 행의 +하위(자식 과업 추가), +동위(형제 과업 추가), ◀ / ▶(레벨 깊이 이동), ▲ / ▼(위아래 순서 이동) 버튼으로 마우스 클릭만으로 WBS 구조를 편집합니다.
  • 계획일정 휴일 자동보정 및 실적 자동반영:
    • 휴일 자동보정 클릭 시 주말·공휴일이 포함된 계획 일정이 영업일로 자동 보정됩니다.
    • 일정/실적 자동반영 클릭 시 선택한 서브시스템 및 기준일자 기준으로 현재 진행 중이거나 완료 도래한 과업만 실적을 자동 계산하며, 과거에 이미 완료된 실적 데이터는 수정하지 않고 보존합니다. 각 행의 자동 버튼으로 개별 과업만 반영할 수도 있습니다.

6. 트러블슈팅 및 자주 묻는 질문 (FAQ)

Q1. 사내 HTTP 주소(http://192.168.x.x)로 접속 시 비밀번호 창에서 넘어가지 않아요.

• 원인 및 해결: 일반 브라우저의 crypto.subtle API는 HTTPS나 localhost에서만 동작합니다. AX Project Management by YS ver1.0.9에는 비보안 HTTP 환경에서도 동일하게 동작하는 순수 JS SHA-256 엔진이 내장되어 있으므로, 구버전 캐시가 남아 있다면 Ctrl + F5(강력 새로고침) 후 사번 admin / 비밀번호 1234를 입력해 주세요.

Q2. 비밀번호를 분실했거나 일반 사용자 사번으로 로그인되어 설정 탭에 못 들어갑니다.

• 해결 방법: 상단 헤더의 현재 로그인 사용자 배지를 확인하고, 설정 탭 클릭 시 나타나는 인증 창에서 관리자 사번(admin)과 관리자 비밀번호를 입력하면 즉시 관리자 권한으로 전환됩니다.

Q3. 간트차트의 1주차 시작일이 프로젝트 시작일과 다르게 표시됩니다.

• 해결 방법: 2026 ver1.0.9부터 간트차트의 주차는 설정 → 1-2. 매주 시작 요일(예: 월요일)을 기준으로 정렬됩니다. 프로젝트 시작일이 수요일이더라도 해당 주의 시작 요일(월요일)부터 1주차가 시작되며, 헤더에 1주차 (MM/DD 요일) 형태로 시작일이 명시됩니다.

Q4. 오프라인 환경에서 본 매뉴얼을 Word(.docx) 파일로 바로 받을 수 있나요?

• 해결 방법: 네, 본 웹 매뉴얼 우측 상단의 [📥 매뉴얼 Word(.docx) 다운로드] 버튼을 누르면 외부 서버나 인터넷 연결 없이도 내장된 정식 Word(.docx) 문서가 즉시 다운로드됩니다. 또한 패키지 내 docs/ 폴더에도 동일한 원본 파일이 포함되어 있습니다.

📅 14. 회의관리 관리 센터 (MeetingManager)

프로젝트 진행 중 발생하는 모든 정기·수시 회의 일정을 월별 캘린더로 관리하고, 회의록(기본정보, 참석자, 안건별 논의·결정사항)을 체계적으로 기록하며, 회의 결과 도출된 Action Item의 이행 상태를 전사 통합 트래커 및 주간보고서와 실시간 연동합니다.

💡 주요 활용 방법:
  • 월별 회의 캘린더: 프로젝트 연도 월별 캘린더에서 날짜를 클릭하여 새 회의를 등록하고, 회의 뱃지를 클릭하면 즉시 회의록 작성 모드로 진입합니다.
  • 안건별 회의록 작성: 회의 안건(Agenda)을 자유롭게 추가하여 상세 발언 내용과 합의된 결정사항을 기록하고, Action Item을 즉시 등록할 수 있습니다.
  • Action Item 통합 관리: Action Item 서브탭에서 전사/서브시스템별 실행과업 목록을 조회하고 원클릭으로 완료 처리합니다.
  • 공식 문서 출력: 작성된 회의록은 독립 Word(.docx) 및 Excel(.xlsx)로 언제든지 출력할 수 있습니다.
