# 검토 — Workgroup 서버를 Java 로 (적은 비용으로)

상태: **검토만 (2026-11)** — 아래 "정할 것"을 사용자가 정하면 진행

## 지금 서버 (바꿀 대상)
- Python 표준 라이브러리만 사용 (외부 패키지 없음): `http.server` · `sqlite3` · `hashlib` · `ssl` · `zipfile`
- 약 3,700줄, 파일 17개 (`workgroup/server/`). 가장 큰 것: 저장 `store.py` 900 · 요청 처리 `handler.py` 480 · 백업 320 · 첨부 310 · 잠금 280
- API 54개, 모두 `POST /api/...` + JSON (조회 1개만 GET). 묶음: 관리 11 · 로그인 8 · 프로젝트 8 · 첨부 7 · 자료 5 · 잠금 5 · 스냅샷 4 · 감사 3 · 채팅 3
- DB: SQLite 파일 2개 (`data/wbs_enterprise.db`, 감사 로그 `data/audit_log.db`). 업무 자료는 대부분 **JSON 덩어리**(`TB_WBS_DATASET` 에 자료 묶음 · 파티션별 JSON + 판 번호) — 표가 적어 옮기기 쉬움
- 화면(`webapp/`)은 서버 언어와 무관 — **그대로 둠**

## 비용을 줄이는 원칙
1. **API 를 한 글자도 바꾸지 않는다** — 주소 · 요청 · 응답 JSON · 오류 코드(`DOWNLOAD_BLOCKED` 등) · HTTP 상태가 같으면 화면 코드는 손대지 않음
2. **DB 파일을 그대로 쓴다** — Java 에서도 SQLite(`sqlite-jdbc`)로 같은 표를 읽고 씀 → 자료 옮기기 없음, 운영 중인 DB 를 Java 서버로 바로 열 수 있음, 되돌리기도 쉬움
3. **암호 기록 호환** — PBKDF2-SHA256 · 600,000회 · 같은 기록 형식을 Java 표준(`PBKDF2WithHmacSHA256`)으로 → 기존 계정 그대로 로그인
4. **이미 있는 시험을 계약서로 쓴다** — 서버 API 시험 36개(`test_server_api.py`)와 Workgroup E2E 116개는 HTTP 로만 서버를 부름. 서버 실행 명령만 바꿀 수 있게 하면 **같은 시험이 Java 서버를 검증** (시험을 새로 쓰지 않음)
5. **파일 하나씩 옮긴다** — Python 파일 = Java 클래스 하나 (이름 · 책임 같게). 옮긴 순서대로 시험이 하나씩 통과
6. **외부 라이브러리 최소**: `sqlite-jdbc` · JSON 1개(Jackson 또는 Gson). 나머지는 JDK 표준

## 방식 선택 (회사 환경에 따라)
| 안 | 모양 | 장점 | 단점 |
|---|---|---|---|
| **A. JDK 내장 HTTP 서버** (`com.sun.net.httpserver`) | 실행 jar 하나 (`java -jar`) | 지금 Python 구조와 1:1, 가장 적은 코드 · 라이브러리, 배포 쉬움 | 회사가 "WAS 위에서만" 허용하면 못 씀 |
| **B. 서블릿 (WAR)** | Tomcat · JEUS 등 회사 WAS 에 올림 | 회사 표준 WAS · 인증서 · 접근 통제를 그대로 씀 | WAS 설정 · 배포 절차가 회사마다 다름 |
| C. Spring Boot | jar 또는 WAR | 회사 표준이 Spring 이면 익숙함 | 라이브러리 · 크기가 커짐, 이 규모엔 과함 |

**권장: 요청 처리 부분만 얇게 나누어 A · B 둘 다 되게** — 업무 코드(저장 · 권한 · 잠금 · 첨부 · 백업)는 공통 클래스, 입구만 `JdkServer`(A) · `ApiServlet`(B) 두 개. 회사 방침이 정해지기 전에 시작할 수 있고, 입구 하나 추가 비용은 약 200줄
- HTTPS: A 는 지금처럼 인증서 파일(PEM → Java 키 저장소 변환 도구 포함), B 는 WAS 가 처리

## 할 일과 순서 (시험이 통과하는 단위)
| 단계 | 내용 | 확인 |
|---|---|---|
| 0 | 시험이 서버 실행 명령을 바꿀 수 있게 (`SERVER_CMD`) — Python 서버로 그대로 통과 | API 36 · E2E 116 |
| 1 | 뼈대: 설정(app.ini) · 로그 · 화면 파일 내려주기 · 보안 머리글 · `app-config.js` 생성 | ping · 정적 파일 시험 |
| 2 | 로그인 · 세션 · 암호(PBKDF2) · 권한 | 인증 · 암호 시험 |
| 3 | 자료 불러오기 · 저장(파티션 · 판 번호 · 충돌) — `store.py` · `permission.py` | 저장 · 권한 · 프로젝트 시험 (핵심) |
| 4 | 잠금 · 감사 로그 · 다운로드 제한 · 스냅샷 · 초기화 | 각 시험 |
| 5 | 첨부(크기 · 확장자 · 내용 검사 · 휴지통) · 백업/복원(zip) | 첨부 · 백업 시험 |
| 6 | 관리(멤버 · 프로젝트), 채팅(꺼져 있으면 나중에) | 남은 시험 전부 |
| 7 | Workgroup E2E 116 · 배포본(jar 또는 war + 실행 bat) · 설치 안내 | E2E · 사용자 확인 |

- 규모 예상: Java 약 4,500~5,500줄 (Python 보다 1.3~1.5배)
- 작업량 예상: 단계 0~3 이 절반. 시험이 이미 있어 "옮기기 → 시험 → 고치기" 반복 — 대화 세션 5~8회 정도
- 이 개발 환경에 JDK 21 · Maven · Gradle 이 있어 여기서 만들고 시험할 수 있음

## 더 줄일 수 있는 것 (사용자 확인 필요)
- **채팅**: 지금 꺼져 있음(`chat=0`). Java 1차에서 빼면 API 3개 · 표 1개 줄어듦
- **HTTPS 직접 처리**: 회사 WAS · 프록시가 맡으면 인증서 코드가 필요 없음
- **예전 DB 올리기(legacy upgrade)**: 이미 모든 설치가 최신이면 Java 에선 빼도 됨
- Python 서버는 Java 가 모든 시험을 통과할 때까지 **함께 유지**(같은 DB 를 쓰므로 문제 생기면 바로 되돌림), 그 뒤 지움

## 정할 것 (사용자)
1. 회사 배포 방식: 실행 jar(A) / 회사 WAS 에 WAR(B) / 둘 다
2. Java 버전 (회사 서버에 깔린 것 — 8 · 11 · 17 · 21). 8 이면 문법 제약이 있어 조금 늘어남
3. DB: SQLite 유지(권장, 가장 적은 비용) / 회사 DB(Oracle · Tibero 등)로 — 후자면 표 정의 · 쿼리 변경이 더해짐 (Enterprise 계획과 겹침)
4. 외부 라이브러리 반입: jar 2개(sqlite-jdbc · JSON) 승인 가능한지
5. 채팅 · HTTPS 직접 처리 · 예전 DB 올리기를 1차에서 뺄지
