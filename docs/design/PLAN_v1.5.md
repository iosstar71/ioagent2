# v1.5 검토안 — 화면 구성 · 업무 흐름

상태: **적용 (v1.5.0)** — 결정: 선행 최대 3개 · 감사 로그 보관 1년 · 열람 Admin · PM(화면은 프로젝트 설정 > 감사 로그) · 다운로드 제한 멤버별. 아래 1장의 "1개"는 3개로 바뀜. 범위: 선행 지연 경고(두 판, **선행 최대 3개**) · 다운로드 제한(**Workgroup 만**) · 감사 로그(Workgroup 만) · 체크인 버튼 아이콘 색(Obsidian · Pop 외 테마에서 잘 안 보임). 원칙은 1.4 와 같음 — 새 칸은 선택 입력, 계산은 엔진(`Metrics` · `WBSEngine`)에.

## 1. 선행 Task 지연 경고 (두 판)

### 무엇을 하나
- Task 에 **선행 Task 1개**를 지정할 수 있음 (선택). 크리티컬 패스 · 일정 자동 밀기는 하지 않음 — 경고만.
- 경고 조건 (하나라도 맞으면 "선행 지연"):
  1. 선행 Task 상태가 **지연**
  2. 선행 Task 의 계획 종료일이 이 Task 의 계획 시작일 **이후** (일정 충돌)
  3. 이 Task 를 실제 시작했는데 선행 Task 가 **미완료**

### 화면
| 위치 | 모양 |
|---|---|
| WBS 상세 패널 | "선행 Task" 입력 (WBS ID 목록에서 고름) + 선행 Task 이름 · 상태 · 계획 종료일 한 줄 |
| WBS 표 | 작업명 앞 ⛓ 표시, 경고면 주황 ⛓ + 말풍선 "선행 1.2.3 지연 (계획 종료 6/10)" |
| WBS 상태 버튼 | "선행 지연 n" 버튼 추가 (누르면 그 Task 만) |
| Gantt | 경고 Task 막대 왼쪽 끝에 주황 점 (연결선은 그리지 않음 — 화면이 복잡해짐) |
| 체크할 일 · My Work | "⛓ 선행 지연 영향 n" 묶음 — 내 Task 의 선행이 늦을 때 |
| 주간보고 · 종합보고서 | 지연 장표에 "선행 지연 영향 Task" 목록 |
| 엑셀 WBS | "선행 Task" 열 (업로드도 받음) |

### 업무 흐름
1. **계획 수립 때** PL 이 서브시스템 사이 · 단계 사이 **꼭 필요한 연결만** 지정 (예: 인터페이스 정의 → 연계 개발)
2. **매일** 담당자는 My Work 의 "선행 지연 영향" 을 봄 → 선행 담당자와 조율
3. **주간 회의** PL 은 WBS 의 [선행 지연] 버튼으로 목록을 보고 → 계획 조정(계획 일정 수정) 또는 이슈로 올림
4. 계획을 바꾸면 1.4 기준선과 비교되어 "기준선 대비 +N일" 로 영향이 보임

## 2. 감사 로그 (Workgroup 만)

Standalone 은 한 PC · 한 사람이 쓰므로 해당 없음.

### 남기는 것 (서버가 기록 — 화면이 보내는 값만 믿지 않음)
| 종류 | 예 |
|---|---|
| 자료 삭제 | 저장할 때 이전 대비 사라진 Task · 요구사항 · VOC · 산출물 행 (ID · 건수) |
| 초기화 · 복원 | 데이터 초기화, 백업 복원, 파일 Merge 반영 |
| 잠금 | 체크아웃 강제 해제 (누가 · 누구의 잠금을) |
| 다운로드 | 엑셀 · 워드 · PPT · 백업 파일 내려받기 (종류 · 범위) |
| 계정 · 권한 | 로그인 실패 연속, 암호 초기화, 권한 · 다운로드 제한 변경, 멤버 추가 · 삭제 |
| 기준선 | 기준선 확정 · 재확정 (사유 포함) |

각 줄: 일시 · 사람(멤버 ID) · 접속 IP · 프로젝트 · 종류 · 대상 · 내용. **화면에서 지우거나 고칠 수 없음** (보관 기간은 `app.ini`, 기본 1년, 지난 것은 서버가 정리).

### 화면
- **Admin > 감사 로그** 탭 (Admin · PM 만 열람): 기간 · 사람 · 종류 걸러 보기, 표, [CSV 내려받기] (이 내려받기도 기록됨)
- Summary 에는 표시하지 않음 (관리 기능)

### 업무 흐름
1. 평소에는 자동 기록만 — 사용자는 할 일 없음
2. **월 1회 또는 감리 · 내부통제 점검 때** Admin 이 기간을 골라 CSV 로 내려받아 제출
3. 사고(자료가 사라짐 등) 때: 감사 로그로 누가 언제 지웠는지 확인 → 백업에서 복원 (복원도 기록됨)

## 3. 다운로드 제한 권한 (Workgroup 만 — 사용자 결정)

### 무엇을 하나
- 멤버마다 **다운로드 허용 / 금지** (프로젝트별). 기본 허용.
- 금지된 멤버: 엑셀 · 워드 · PPT · 백업 · 파일 Merge 내려받기 버튼이 비활성 (말풍선 "다운로드가 제한된 계정입니다 — PM 에게 요청하세요")
- **서버도 거부** (백업 · 파일 내려받기 API). Standalone 에는 넣지 않음 (한 PC 라 강제 수단이 없음)
- 화면을 보고 · 고치는 것은 그대로 가능. 화면 캡처 · 복사까지 막지는 못함 (통제 + 기록이 목적)

### 화면
| 위치 | 모양 |
|---|---|
| Admin > 멤버 | "다운로드" 열 (허용 / 금지 선택) — PM 이상만 바꿈 |
| 다운로드 버튼 | 금지면 비활성 + 말풍선 |
| 머리글 사용자 메뉴 | "다운로드 제한 계정" 표시 |

### 업무 흐름
1. 프로젝트 시작 때 PM 이 **협력사 · 외부 인력 계정**을 "금지"로 지정
2. 자료가 필요하면 PM(또는 허용된 PL)에게 요청 → PM 이 내려받아 전달 (감사 로그에 남음)
3. 인력 철수 때 계정 비활성화
