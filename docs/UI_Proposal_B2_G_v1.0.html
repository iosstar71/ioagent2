절충안 B2 — 위쪽 메뉴가 스크롤되지 않는 2단 메뉴

절충안 B의 장점(넓은 표·간트 화면, 한 줄 머리글, 화면별 작업 버튼)을 유지하면서, 탭 14개가 한 줄에 들어가지 않아 생기던 가로 스크롤을 없앤 개선안입니다. 메뉴를 업무 묶음 4개와 그 안의 하위 메뉴로 나누고, 관리 메뉴는 머리글의 톱니바퀴로 옮깁니다.

1024px 화면까지 스크롤 없음 모든 화면 최대 2번 클릭 기본 언어 한국어 배치 파일 v1.2.0 과 공용
1 · 문제 확인

현재 위쪽 메뉴는 1,503px 이 필요합니다

v1.0.10 화면에서 탭 줄의 실제 폭을 재어 보면, 1,600px 이상 모니터에서만 한 줄에 다 보이고 그보다 좁으면 오른쪽 탭이 가려져 가로 스크롤이 생깁니다. 사내 노트북(1366px)·FHD 125% 배율(1536px)에서 바로 발생합니다.

1920px가려짐 0개
1600px가려짐 0개
1440px가려짐 1개
1366px가려짐 1개
1280px가려짐 2개
1024px가려짐 5개

막대는 화면 폭이 탭 줄 필요 폭(1,503px)의 몇 %를 담을 수 있는지, 빨간 선은 필요 폭 위치입니다. 측정: v1.0.10 index.html, Chromium.

2 · 방안 비교

메뉴를 줄이는 네 가지 방법

방법내용클릭 수판단
드롭다운 묶음위쪽에 묶음 5개만 두고 누르면 하위 메뉴가 펼쳐짐항상 2번자주 쓰는 화면도 2번
더보기(우선순위 메뉴)들어가는 만큼 탭을 보이고 나머지는 [더보기 ▾]로 이동1~2번화면 폭마다 위치가 바뀜
왼쪽 메뉴 (개편안 A)세로 메뉴 5묶음, 접으면 아이콘만1번WBS·간트 폭 170px 감소
2단 메뉴 (B2 권장)한 줄 안에 업무 묶음 4개 + 선택한 묶음의 하위 메뉴를 함께 표시. 관리 메뉴는 톱니바퀴로같은 묶음 1번, 다른 묶음 2번권장

업무는 대부분 한 묶음 안에서 이어집니다(WBS ↔ 간트, 주간보고 ↔ 회의). 같은 묶음 안의 이동은 지금처럼 한 번 클릭이고, 묶음을 바꾸면 그 묶음에서 마지막으로 보던 화면이 열립니다. 왼쪽 메뉴(개편안 A)는 없애지 않고 선택 설정으로 남겨, 세로 메뉴를 선호하는 사용자가 고를 수 있게 합니다.

4 · 구성

메뉴 배치

위치항목
머리글 (48px)로고 · 프로젝트 선택 · 보고 기준일 · 검색(Ctrl+K) · 저장 상태 + [전체 저장] · 공지(숫자) · 도움말 · ⚙ 관리 · 사용자(언어·비밀번호·잠금·로그아웃)
메뉴 줄 (42px)개요: 홈 · 대시보드 · 단계별 진척 / 일정: WBS 공정 · 간트차트 / 범위·품질: 요구사항 · VOC·이슈 · 산출물 / 보고·협업: 주간보고 · 회의관리 · 공지·소통
⚙ 관리 메뉴기준정보 · 스마트 병합 · 시스템 설정 · 프로젝트 관리 · 법적 고지 (권한이 없으면 숨김)
즐겨찾기 (선택)메뉴 줄 오른쪽에 자주 쓰는 화면 최대 3개를 고정. 1280px 미만에서는 숨김
아래 고정 줄저장하지 않은 변경 n건 + [변경 취소] [모두 저장 (Ctrl+S)] — DB 서버 모드에서만 표시
메뉴 위치 (선택 설정)기본: 위쪽 2단 메뉴. [사용자 메뉴 > 화면 설정 > 메뉴 위치]에서 왼쪽 메뉴를 고를 수 있습니다. 같은 메뉴 정의(묶음 4개 + 하위 메뉴 + ⚙ 관리)를 세로로 그리며, 접으면 아이콘만 남아 64px 만 차지합니다. 사용자마다 저장되고, 관리자는 기본값을 정할 수 있습니다.

가장 넓은 묶음(보고·협업)도 묶음 4개 + 하위 메뉴 3개 + 즐겨찾기를 합쳐 약 880px 로, 1024px 화면에 들어갑니다. 메뉴 이름이 길어지는 영어 화면도 같은 폭 안에 들어가도록 하위 메뉴는 짧은 이름(Dashboard, WBS, Gantt, VOC 등)을 씁니다.

5 · 최신 화면 흐름 반영

개편안 A 에서 다시 가져온 요소

  • 명령 검색 (Ctrl+K): 화면 이름·WBS ID·요구사항/VOC 번호·사용자로 바로 이동. 메뉴를 몰라도 원하는 화면에 도달합니다.
  • 오른쪽 상세 패널: WBS·요구사항·VOC 행을 고르면 열리는 편집 패널. 표에서 바로 고치는 기존 방식은 유지합니다.
  • 요약 우선 대시보드: 핵심 숫자 4개 → S-커브 → "확인할 일"(지연 Task·미작성 주간보고·미조치 VOC) 순서.
  • 상태는 색 + 글자: 완료·진행·지연을 색 칩과 글자로 함께 표시 (색약 사용자 고려).
  • 화면 밀도 2단계: 기본 / 촘촘 (표가 많은 화면용). 테마 3종(Navy · Teal · Graphite)과 따로 고릅니다.
6 · 언어

기본 언어는 한국어

  • 설계 문서·화면 시안은 영어로 만들 수 있지만, 프로그램의 언어 기본값은 한국어(ko) 로 고정합니다.
  • 적용 위치: 첫 실행 언어, 로그인 화면 언어 선택의 첫 값, 신규 사용자 등록 기본값, 관리자 일괄 언어 설정의 기본 선택.
  • 사용자가 English 를 고르면 그 사용자에게만 저장되며, 다음 로그인부터 적용됩니다 (현재 v1.0.10 과 같은 방식).
  • G 버전에서 언어 파일을 키 기반으로 바꾸더라도 DEFAULT_LANG = "ko" 를 설정 파일에서 지정하고, 자동 테스트에 "첫 실행 = 한국어" 항목을 둡니다.
7 · 배치 파일

v1.2.0 과 같은 배치 파일 사용

국내판(v1.2.x)과 G 버전이 같은 배치 파일을 그대로 쓰도록, 제품마다 다른 값은 배치 파일이 아닌 설정 파일 한 곳에 둡니다.

파일공용 방식
run_server.bat두 버전 동일. 서버 실행 파일 이름(wbs_db_server.py)·포트·로그 폴더·HTTPS 인증서 위치는 같은 규칙 사용. 제품 이름은 서버가 스스로 출력
make_cert.bat두 버전 동일 (tools/make_cert.py 공용)
run_tests.bat두 버전 동일. 각 버전의 tools/tests 폴더를 실행
build_standalone.bat두 버전 동일 (tools/build_standalone.py 가 index.html 기준으로 동작)
app.ini (신규)제품별로 다른 값만 보관: 제품 이름, 기본 포트(8080), 기본 언어(ko), DB 파일 이름. 배치 파일은 이 파일을 읽기만 함

변경이 필요할 때의 순서

  1. 배치 파일 변경은 국내판 v1.2.x 저장소에서 먼저 하고 v1.2.x 패치(v1.2.1 …)로 배포합니다.
  2. 같은 커밋을 G 저장소에 가져옵니다 (배치 파일·tools/make_cert.py·tools/make_release*.py 는 두 저장소에서 내용이 같아야 함).
  3. 두 저장소의 자동 테스트에 "배치 파일 동일 여부" 검사를 넣어, 한쪽만 바뀌면 테스트가 실패하도록 합니다.
  4. G 에만 필요한 기능은 배치 파일이 아닌 app.ini 값이나 서버 실행 옵션으로 추가합니다.
