■ [IOSTAR-PM 이름의 뜻]
  - In-situ Operations   : 외부 클라우드 통신 없이 폐쇄망 현장에서 완결되는 운용
  - Smart Tasks          : 4레벨 WBS 기준선, 공정률 자동 롤업, 공휴일 보정의 지능형 과업 체계
  - Accurate Resources   : 투입 공수(M/M) 누적과 지연 조기 감지로 오차 없는 자원 통제
  - Project Manager      : 실무진과 C-Level이 직관적으로 지휘하는 실전 프로젝트 사령탑
  핵심 강점: 폐쇄망 완전 자립(Zero-dependency, 경량 SQLite) · 핵심 리소스 정밀 추적(S-Curve, 크리티컬 패스)
            · 순수 바이트스트림 산출물 생성(DOCX 보고서, 다중 시트 XLSX)

■ [빠른 시작]
  1) 압축 해제 후 index.html (또는 Standalone.html) 더블클릭 → 로컬 저장소(LocalStorage) 모드로 실행
     - 최초 실행 시 data/initial_data.json 초기 데이터가 브라우저 로컬 저장소에 설정됨
     - 로그인: 기본 관리자 admin / 1234 (로그인 화면에서 [👤 신규 사용자 등록] 가능, 기본 권한: 일반 사용자)
     - 로그인 화면에서 언어(한국어 / English) 선택
  2) 다중 사용자 공유: run_server.bat 실행 → http://<서버IP>:8080 접속
     → admin 로그인 후 [⚙️ 시스템 설정 > DB 연동]에서 [🪶 SQLite 파일 DB] 선택 → 화면 재로드 후 서버 로그인
     - 서버는 로그인 토큰 인증 필수 (기존 v1.0.5 DB는 최초 기동 시 자동 이관)

■ [ver1.0.10 개선 내역] — 보안 강화 · 여러 프로젝트 · Windows 패키지
1. 비밀번호 보안
   - 서버 저장: 브라우저 1차 해시(SHA-256)를 사용자별 솔트 + PBKDF2-SHA256(600,000회)으로 다시 해시하여 저장
     (형식 pbkdf2_sha256$반복$솔트$해시, 비교는 상수 시간). v1.0.9 이하 비밀번호는 서버 첫 기동 때 자동 전환
   - 초기 비밀번호(1234)·관리자 지정 임시 비밀번호로 로그인 시 비밀번호 변경 필수 (변경 전에는 서버 데이터 API 차단)
   - 새 비밀번호 규칙: 8자 이상, 영문+숫자 포함, 초기 비밀번호·쉬운 비밀번호 금지
   - 일반 사용자는 사용자 데이터 저장으로 비밀번호를 바꿀 수 없음 (비밀번호 변경 API 로만 변경)
   - 시스템관리자 권한은 시스템관리자만 부여 가능
2. 통신 암호화 (HTTPS)
   - make_cert.bat (tools/make_cert.py): OpenSSL 없이 사내 CA + 서버 인증서(RSA 2048, SHA-256, 397일) 생성
     → certs\ca.crt 를 접속 PC 의 [신뢰할 수 있는 루트 인증 기관]에 설치 (그룹 정책 배포 가능)
   - run_server.bat: certs\server.crt + certs\server.key 가 있으면 자동으로 HTTPS(TLS 1.2 이상) 기동
     (직접 실행: python wbs_db_server.py --cert certs/server.crt --key certs/server.key)
   - HTTPS 사용 시 HSTS 헤더 전송, 인증서·개인키 파일은 웹으로 내려받을 수 없게 차단, 배포 zip 에서 제외
3. 스크립트 실행 제한 (콘텐츠 보안 정책, CSP)
   - 화면의 인라인 스크립트(onclick 등 478개)를 모두 data-click 등 선언형 속성 + js/ui-events.js 로 전환
   - 서버는 index.html 에 Content-Security-Policy: script-src 'self' (인라인·외부 스크립트 실행 차단) 전송
   - 다른 사이트(Origin)에서의 API 호출 차단 (CORS 는 같은 서버 주소만 허용, --allow-origin 으로 추가 가능)
4. 여러 프로젝트 관리
   - 머리글 [프로젝트 선택]으로 전환, [🗂️ 프로젝트 관리]: 만들기(현재 프로젝트 기준정보 복사 선택) · 이름 변경 ·
     참여자 지정(참여자만 접근) · 보관(읽기 전용) · 삭제(시스템관리자)
   - 프로젝트별 저장: WBS·요구사항·VOC·산출물·회의·주간보고·공지·소통·채팅·기준정보
     공통: 사용자 계정, 화면 테마 / 기존 데이터는 "기본 프로젝트(DEFAULT)"로 그대로 사용 (이관 불필요)
   - 프로젝트별 권한: [기준정보 > d. 사용자 정보]에서 현재 프로젝트의 권한·담당 서브시스템 지정
     (지정하지 않은 사용자는 기본 역할 사용, 시스템관리자는 모든 프로젝트 관리자)

■ [ver1.0.8 개선 내역]
1. 접속 방식과 저장소 모드 불일치 방지
   - 서버 주소(http://서버IP:8080)로 접속 + 로컬 저장소 모드 → 로그인 전에 "서버 DB 모드로 전환하시겠습니까?" 확인
     (이 브라우저에서 저장소 모드를 고른 적이 없으면 서버 DB 모드를 기본값으로 사용)
   - index.html 파일 직접 실행 → 로컬 저장소 모드로 전환하여 로그인, 서버 DB 모드 접속 방법(서버 주소) 안내
   - 서버 DB 모드에서 서버가 꺼지면 상단 빨간 경고 배너 + 저장 버튼 비활성화, 다시 켜지면 자동 해제 (20초 주기 확인)
2. WBS 실적 자동반영 (행 단위 [⚡실적] / 전체 [⚡ 실적 자동반영])
   - 100% 반영 시 실적완료일: 계획완료일이 기준일과 같은 주차이면 계획완료일, 아니면 기준일
   - 실적시작일이 실적완료일보다 미래이면 실적시작일 = 실적완료일
   - 상태 판정: 계획 진척률보다 실적이 1%p 이상 적으면 '지연' — 상태(status)를 데이터에 저장
   - [🚦 상태 조회 (최하위 Task)]: 지연/진행중/착수전/완료 최하위 Task 만 모아 조회, 지연 건수 배지
3. 간트차트: WBS 목록과 차트를 하나의 스크롤 영역으로 통합 (목록 좌측 고정 · 날짜 머리글 상단 고정 · 같은 행 강조)
4. 주간보고

■ [대용량 데이터(수천 행 이상) 대응 방안 — 검토 결과]
 현재 구조: 데이터 변경 시 rebuildAll() 이 재계산 후 WBS·간트·대시보드 등 모든 화면을 다시 그림.
 측정 기준(현 샘플 232행)은 문제 없으나, 5,000행 이상에서는 입력 1건마다 수백 ms~수 초 지연이 예상됨.
 권장 단계별 대안:
  ① [1단계 · 효과 큼 · 적용 쉬움] 보이는 탭만 다시 그리기
     - rebuildAll 에서 재계산은 유지하되 렌더링은 현재 활성 탭만 수행, 나머지 탭은 "갱신 필요" 표시 후 탭 진입 시 그림
  ② [1단계] WBS 표 가상 스크롤 (virtual scrolling)
     - 화면에 보이는 30~50행만 DOM 으로 만들고 스크롤 위치에 따라 교체 → 행 수와 무관하게 일정한 속도
     - 간트차트도 같은 방식(목록·차트가 이미 단일 스크롤 영역이라 적용 용이)
  ③ [2단계] 증분 재계산
     - 진척 롤업을 변경된 서브시스템(파티션)만 다시 계산 (현재 저장 계층의 파티션 구조 재사용)
     - 변경 감지(diff)도 변경된 파티션만 비교하도록 dirty 플래그 도입
  ④ [2단계] 입력 디바운스 · 배치 처리: 연속 입력은 300ms 묶어서 1회 재계산
  ⑤ [3단계 · 데이터 수만 행] 서버 측 페이징 / 서브시스템 단위 지연 로딩
     - 로그인 시 담당 서브시스템만 불러오고, 통합 화면(대시보드)은 서버가 집계한 요약값 사용
     - 계산 로직을 Web Worker 로 분리하여 화면 멈춤 방지
 권장 순서: ①+② (체감 효과 대부분) → 데이터 증가 추이에 따라 ③④ → 필요 시 ⑤

   - file:// 환경에서도 동작하도록 js/initial-data.js 에 동일 데이터 내장 (JSON 수정 후 python tools/build_initial_data.py)

■ [ver1.0.4 공식 운영 오픈 핵심 개선 내역]

1. 주간보고 회의 일정 레이아웃 및 DOCX 보고서 중복 정리
   - [UI 개선] 주간보고 탭의 [금주 회의 실적]과 [차주 회의 계획]을 위아래(Vertical Column)로 배치하여 차주 회의 일정과 상정 안건의 시인성을 대폭 강화
   - [DOCX 중복 제거] 주간보고 DOCX 출력물 목차에서 내용이 중복되던 "6. 금주 및 차주 프로젝트 주요 회의 일정 (Meeting Schedules)" 섹션을 완전히 삭제하고, "6. 주간 회의 진행 실적 및 차주 회의 계획 (회의록·Action Item 연동)"로 정돈 일원화

2. 소통 패드 및 시스템 설정 스타일 설정 일원화
   - [위치 정상화] 소통 패드(공지/소통 탭)에 중복 표시되던 '엑셀/DOCX 스타일 및 폰트 설정 카드' 2건을 완전히 제거
   - [시스템 설정 이동] 시스템 설정(⚙️ 설정) 탭의 노후 분리 설정 카드를 삭제하고, 단일 통합 '엑셀(XLSX) · 워드(DOCX) 공통 보고서 스타일 및 폰트 설정 카드'로 교체

3. 홈 화면(하이브리드 스마트 포털 / 이그제큐티브 브리핑 룸) 위젯 연동 및 네비게이션 고도화
   - [하이브리드 스마트 포털] 공지사항 및 실시간 소통 피드 데이터(noticesData, communicationsData)가 100% 정상 로드되도록 연동 복구
   - [원클릭 탭 이동] 공지사항 클릭 시 [공지사항 서브탭]으로, 소통 피드 클릭 시 [소통 피드 서브탭]으로 즉시 자동 이동
   - [스마트 워크벤치 위젯] 3대 업무 요약 카드(요구사항, 산출물, VOC) 및 미완료 Task 클릭 시 해당 관리 탭으로 즉시 네비게이션
   - [이그제큐티브 브리핑 룸] 전사 달성률 히어로 배너 및 5대 핵심 경영 KPI 스트립(WBS, 지연, REQ, 산출물/VOC) 클릭 시 WBS 및 각 관리 탭으로 즉시 전환

4. 시스템 명칭 및 버전 정보 전사 표준 일원화
   - 상단 메뉴탑(Header), 오프라인 매뉴얼(manual.html), 소프트웨어 아키텍처 정의서(architecture.html), 배치 프로그램(run_server.bat), 파이썬 DB 서버(wbs_db_server.py), README.txt 모두 동일하게 [IOSTAR-PM ver1.0.4]으로 통일

5. 엑셀 / DOCX 통합 스타일 엔진 및 파스텔 소프트 테마군 추가
   - [단일 스타일 일원화] 엑셀과 DOCX 보고서의 스타일 선택을 완전히 하나로 통합하여 설정 변경 시 엑셀과 워드에 즉시 동일 반영
   - [전체 테이블 스타일 100% 적용] Word(DOCX) 주간보고서 및 회의록에서 첫 번째 테이블뿐만 아니라 세부 추진실적, 차주 계획, 회의록, Action Item 등 모든 테이블에 테마 색상(헤더 배경, 텍스트 색상, 테두리, 서체, 폰트 크기)이 완전하게 반영되도록 엔진 개선
   - [신규 감성 파스텔 테마 추가] 기존 공식 엔터프라이즈 테마에 더해 은은하고 부드러운 7대 감성 파스텔 테마(Pastel Sky Blue, Pastel Mint, Pastel Lavender, Pastel Warm Peach, Pastel Rose Pink, Pastel Soft Lemon, Pastel Sage Gray) 신규 탑재

6. 소통 피드 칸반보드(Kanban Board) 카드 제목 노출 및 전용 안건 제목 입력 지원
   - [제목 노출] 칸반보드 및 피드 뷰에서 각 소통 카드의 핵심 안건 제목(Title)이 상단에 굵고 선명하게 노출되도록 개선
   - [안건 입력] 소통 피드 작성 창에 WBS 연계 Task ID와 함께 안건 제목 입력란(commPostTitleInput)을 신설하여 체계적인 토론 안건 카드 생성 지원

7. 상단 헤더 긴급공지 바로가기 카운트 정확도 개선
   - [필터 정상화] 상단 헤더 긴급공지 배지(headerNoticeCountBadge)가 상단 고정(isPinned) 여부와 혼동되지 않고, 실제 긴급(priority === '긴급') 공지만 정확히 선별 카운트하도록 필터 로직 정비 (현재 긴급 1건 정상 노출)

8. 회의관리 캘린더 전면 테마(Color Theme) 완벽 연동
   - [캘린더 테마 반영] 회의관리 캘린더 컨테이너, 네비게이션 바, 요일 헤더, 일자 셀, 당일(Today) 강조 링 등에 CSS 테마 변수(var(--primary), var(--bg-card), var(--lvl-1-bg) 등)를 전면 적용
   - [실시간 리렌더링] 상단 헤더 또는 설정 탭에서 시스템 컬러 테마 변경 시 회의 캘린더가 즉시 새로운 테마 컬러로 자동 동기화 리렌더링

9. 시스템 UI 화면 테마 및 보고서 출력 테마 인기 7대 핵심 테마로 정돈 (v1.0.4)

   - [보고서 출력 테마 7종] Official Blue, Emerald Green, Nordic Teal, Slate Charcoal, Executive Purple, Pastel Sky Blue, Pastel Mint

10. 회의 캘린더 요일 타이틀(월,화,수,목,금) 및 회의 카드/날짜 고대비 시인성 100% 확보
   - [요일 헤더 시인성 복구] 평일(월~금) 헤더 글자색을 고대비 다크 텍스트(var(--text-main, #1e293b))로 지정하여 어떤 테마에서도 선명하게 노출

   - [매뉴얼 동기화] manual-viewer.js 내부에 Base64로 내장된 독립 팝업 매뉴얼(standaloneManualHtmlB64)을 ver1.0.4 manual.html로 완전히 갱신하여 로컬 file:// 및 오프라인 환경에서도 항상 최신 매뉴얼이 열람되도록 조치
