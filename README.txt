================================================================================
Project Mgmt (협업) v1.0.0 — 전사 시스템 하위 서비스용 프로젝트 관리
   - 주소: https://xxx.com/pprjmgmt/   (하위 주소는 conf/app.ini [server] base_path)
   - 폴더 하나(pprjmgmt)에 모두 들어 있음, 운영 중 전체 용량 10MB 이하 기준
   - 브랜치: project-mgmt-collab
================================================================================

■ 폴더 (pprjmgmt/)
  conf/app.ini        설정 — 제품 이름 · 버전 · 하위 주소 · 포트 · DB 파일 · 체크아웃 규칙
  server/             서버 프로그램 (Python 3.8+ 표준 라이브러리만)
  webapp/             화면 (index.html + static/)
  data/               DB 파일(pprjmgmt.db, 처음 실행 때 생성) + initial_data.json(처음 상태: admin 하나)
  logs/error.log      오류만 기록 (256KB 를 넘으면 뒤쪽 절반만 남김) — 오류가 없으면 생기지 않음
  legal/              오픈소스 고지 (Pretendard 글꼴)
  start_server.py     서버 실행    run_server.bat / run_server.sh  실행 도우미

■ 설치 · 실행
  1) pprjmgmt 폴더를 서버에 복사
  2) python3 start_server.py  (또는 run_server.bat / run_server.sh)  → http://<서버>:8080/pprjmgmt/
     옵션: --port 8080  --host 0.0.0.0  --quiet(오류를 화면에 출력하지 않음)
  3) 전사 웹 서버(리버스 프록시)에서 https://xxx.com/pprjmgmt/ 아래 요청을 이 서버로 넘김
     (앞부분 /pprjmgmt 를 떼고 넘겨도, 그대로 넘겨도 동작. HTTPS 는 전사 웹 서버가 담당)
     예) Nginx:  location /pprjmgmt/ { proxy_pass http://127.0.0.1:8080/pprjmgmt/; }
  4) 처음 작업자: admin / 1234 (처음 고를 때 새 암호로 바꿔야 함). 프로젝트 정보는 비어 있음

■ 작업자 선택 (로그인이 아님)
  - 전사 시스템의 로그인(SSO) · 사용자 관리와 별개로, 이 프로그램 안에서 일하는 "작업자"를 고르는 화면
  - ① 작업할 프로젝트 → ② 작업자(목록에서 고르거나 작업자 ID 입력) → ③ 작업자 암호 → [▶ 작업 시작]
  - 작업자 등록 · 역할(관리자 / PM / 리더 / 작업자) · 담당 서브시스템은 관리자 · PM 이 정함
    [시스템 설정 > 👥 전체 작업자] (관리자), [기준정보 > 작업자 정보] (PM)
  - 자가 등록 · 암호 자가 초기화는 없음 (암호를 잊으면 관리자 · PM 이 1234 로 초기화)

■ 동시 작업: 서브시스템 체크아웃 · 체크인 (conf/app.ini [lock])
  - lock_mode=required: 서브시스템의 WBS · 요구사항 · 산출물 · VOC 는 📝 체크아웃해야 저장, 끝나면 ✅ 체크인
  - 다른 사람이 체크아웃한 서브시스템은 읽기 전용, 저장하면 거부 → ⏸ 보류(브라우저 보관) / 💾 내 변경 백업 / 🗑 버리기
  - 그 사람이 체크인한 뒤 체크아웃하면 3자 비교(받았던 때 · 다른 사람 결과 · 내 것)로 합침
  - lock_hours=4: 활동할 때마다 연장, 지나면 다른 사람이 체크아웃 가능. PM · 관리자는 사유를 남기고 강제 해제
  - 현황 · 기록: [🔀 스마트 병합 > 🔐 체크아웃 현황]
  - 화면은 일정 시간마다 서버에 묻지 않음 (사용자가 무언가를 할 때만 통신)

■ 용량 10MB 관리
  - 배포 묶음 약 2.7MB (풀었을 때) — tools/make_release.py 가 5MB 를 넘으면 배포를 막음
  - 서버에 쌓이는 것은 DB 하나뿐: 첨부파일 · 채팅 · 서버 백업 폴더 · 복원 지점 파일 · 접속 로그 없음
  - [시스템 설정 > 🗄️ 데이터 관리]: 사용 용량(한도 대비 %) · 🧹 DB 정리(지운 자료 공간 반환) · 프로젝트 초기화
  - 체크아웃 기록은 프로젝트마다 최근 300건만 보관
  - 끝난 프로젝트는 [💾 백업 · 복원]에서 파일로 받은 뒤 지우고 DB 정리

■ 백업 · 복원 (관리자 · PM)
  - 프로젝트 백업 · 복원: 엑셀 / JSON (PC 로 내려받기)
  - 시스템 전체: [📥 시스템 백업 내려받기 (.db)] / [📤 백업 파일로 복원] (복원 전에 지금 상태를 자동으로 먼저 내려받음)
  - 복원 지점: 올리기 · 초기화 전에 자동으로 이 브라우저에 남김
  - 초기화(Task 정보 · 프로젝트 전체 · 완전 초기화)는 관리자만, 대상 프로젝트 이름을 입력해 확인

■ 이 판에서 뺀 것

  · Oracle/Excel/Access 연동 선택 · 로컬 파일 동기화 · 서버 연결 감시 · HTTPS 인증서 도구 · 서버 백업 목록 · 자동 백업 · 접속 로그
