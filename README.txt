■ [IOSTAR-PM 이름의 뜻]
  - In-situ Operations   : 외부 클라우드 통신 없이 폐쇄망 현장에서 완결되는 운용
  - Smart Tasks          : 4레벨 WBS 기준선, 공정률 자동 롤업, 공휴일 보정의 지능형 과업 체계
  - Accurate Resources   : 투입 공수(M/M) 누적과 지연 조기 감지로 오차 없는 자원 통제
  - Project Manager      : 실무진과 C-Level이 직관적으로 지휘하는 실전 프로젝트 사령탑
  핵심 강점: 폐쇄망 완전 자립(Zero-dependency, 경량 SQLite) · 핵심 리소스 정밀 추적(S-Curve, 크리티컬 패스)
            · 순수 바이트스트림 산출물 생성(DOCX 보고서, 다중 시트 XLSX)

■ [빠른 시작]
  1) 압축 해제 후 index.html (또는 Standalone.html) 더블클릭 → 로컬 저장소(LocalStorage) 모드로 실행
     - 최초 실행 시 data/initial_data.json 초기 데이터가 브라우저 로컬 저장소에 설정됨
     - 로그인: 기본 관리자 admin / 1234 (시스템관리자는 프로젝트를 고르지 않아도 됨)
     - 그 밖의 사용자는 로그인 화면에서 프로젝트를 골라 들어감 ([👤 신규 사용자 등록]도 고른 프로젝트에 일반 사용자로 가입)
     - 로그인 화면에서 언어(한국어 / English) 선택
  2) 다중 사용자 공유: run_server.bat 실행 → http://<서버IP>:8080 접속
     → admin 로그인 후 [⚙️ 시스템 설정 > DB 연동]에서 [🪶 SQLite 파일 DB] 선택 → 화면 재로드 후 서버 로그인
     - 서버는 로그인 토큰 인증 필수 (기존 v1.0.5 DB는 최초 기동 시 자동 이관)

■ [v3.2.0] — 큰 글씨 1단계 (글자 크기 토큰) · WBS 칸 접기에 가중치 · REQ ID 추가
1. 글자 크기 [🎨 화면 > 글자 크기]: 화면 전체 확대 대신 글자만 커지는 방식으로 변경 (보통 100% / 크게 115% / 아주 크게 130%)
   - 화면 곳곳에 숫자로 박혀 있던 글자 크기 778곳을 글자 크기 토큰(--fs-xs · --fs-sm · --fs-base … , 기준값 --fs-scale)으로 바꿈
   - 머리글 · 메뉴 · 단추 · 입력 칸 높이가 글자에 맞춰 늘어남, 크게 이상에서는 머리글의 일부 표시(검색 글자 · 저장 시각 · 버전)를 줄여 한 줄 유지
   - 130% 에서도 모든 화면에서 페이지 가로 넘침 없음 (넓은 표 안에서만 가로 스크롤)
   - WBS 입력 칸(날짜 · 숫자 · 담당자 등)도 글자 크기에 비례해 넓어져 글자가 잘리지 않음
   - 2단계(검토 중): 넓은 표(WBS · 주간보고 · 요구사항 · VOC · 산출물)를 칸 중요도에 따라 정리
2. WBS 칸 접기: [◀ 가중치·REQ·담당자·산출물 접기] — 가중치 · REQ ID 도 함께 접힘 (접으면 크게 · 아주 크게에서도 1440px 화면에 표 전체)

■ [v3.1.0] — 주간보고 양식·파일 이름 규칙 · 작성 시점 자료 · 보고서 테마 5가지 · 화면 메뉴 · 글자 크기 · WBS 칸 접기
1. 주간보고 파일 이름 규칙: {파일약칭}_주간보고_{yyyy}W{주차}_{범위}_{양식}_{판}.{확장자}
   - 예) P001_주간보고_2027W22_ALL_DOC-T_v2.docx  (범위 ALL / S-서브시스템 / D-분야, 양식 XLSX / DOC-T 표 포함 / DOC-N 서술형)
   - 판: 작성 완료할 때마다 v1, v2 … / 작성 완료 전 DRAFT / 작성 완료본 없이 자동 생성 AUTO
   - 파일 약칭: [시스템 설정 > 보고서 양식]에서 지정 (비우면 프로젝트 ID, 기본 프로젝트는 PRJ)
   - 공백 · 괄호 · 물결표 등 특수문자 없이 만들어 메일 첨부 · 문서관리 시스템에서도 안전, 주차 순으로 정렬됨
2. 지난 주간보고는 작성 시점 자료로: [작성 완료] 할 때 지표 · 요구사항 · VOC · 회의 · Action Item 을 보고서와 함께 저장
   - 화면 · 엑셀 · 워드 모두 그 자료로 표시 (화면 위쪽에 '📌 작성 완료 시점 자료' / '⏱ 현재 자료 기준' 표시, 문서 번호 표시)
   - v3.1.0 이전에 작성 완료한 보고서는 저장된 자료가 없어 현재 자료로 표시 — 다시 [작성 완료]하면 그 시점 자료가 저장됨
3. 엑셀 · 워드 같은 목차: 1. 개요 및 핵심 지표 / 2. 금주 추진 실적 / 3. 차주 추진 계획 / 4. 이슈 · 요구사항 · VOC / 5. 회의 · Action Item / 6. 작성 현황
   - 엑셀은 목차별 시트, 워드는 표 포함 · 서술형 두 가지 / 금주 · 차주 표에 WBS 담당자 칸
   - Action Item 은 그 주에 도출 · 마감되었거나 아직 끝나지 않은 것만 (이전: 전체)
   - 작성자 · 프로젝트명이 비어 있을 때 넣던 예시 이름(김총괄 수석PM 등) 삭제, 결재란 없음
4. 홈 [📊 브리핑]의 경영 보고: 기준일 주차의 통합 주간보고(주간보고 화면 위쪽 내려받기와 같은 결과) — 작성 현황 · 자료 기준 · 파일 이름 표시
   - 이전에는 그때 열려 있던 주간보고 초안(사용자에 따라 서브시스템 초안)을 내려받아 결과가 달랐음
5. 보고서 테마 5가지: 네이비(기본) · 오피스 블루 · 그레이 · 그린 · 매트 슬레이트(화면 Matte 와 비슷한 무광) — 예전 테마는 가까운 테마로 자동 변경
6. 주간보고 화면: 담당자 칸 추가, 레벨은 WBS ID 아래로, 계획 일정과 완료일을 한 칸에, 상세 내용은 2줄 입력 칸(늘릴 수 있음)으로 넓게
7. 머리글 오른쪽 단추에 글자 표시: [❔ 도움말] [🎨 화면] [⚙ 관리] — [🎨 화면]에서 테마 견본 · 글자 크기 · 메뉴 위치 · 밀도 선택
8. 글자 크기(큰 글씨): 보통 100% / 크게 115% / 아주 크게 130% — 화면 전체를 확대, 사용자마다 기억
   - 넓은 표(WBS 등)는 크게 · 아주 크게에서 가로 스크롤이 생길 수 있음 → WBS 는 담당자 · 산출물 칸을 접어 사용
9. WBS: 날짜 옆 요일 다시 표시(토 파랑 · 일 빨강), [◀ 담당자·산출물 접기] — 접으면 1440px 화면에 표 전체, 펼치면 칸을 넉넉하게(가로 스크롤)
   - 사용자마다 기억, 처음에는 화면 폭이 1600px 보다 좁으면 접힌 상태

■ [v3.0.2] — WBS 담당자 · 상태 칩 필터 확대 · 로그인 화면 비밀번호 초기화 · 화면 정리
1. WBS 담당자 칸 (산출물 앞, 1명)
   - 이 프로젝트 사용자 목록에서 고르거나 직접 입력 (쉼표 등으로 여러 명을 넣으면 첫 번째만 저장)
   - 상위 Task 에 지정하면 하위 Task 에 자동 지정: 비어 있거나 이전 상위 담당자와 같은 하위만 바뀌고, 다른 담당자가 따로 지정된 하위는 유지
   - 새 하위 · 동위 Task 는 상위 담당자를 이어받음 / 상세 패널 · 엑셀 내려받기 · 올리기에도 '담당자' 칸
   - WBS 표 폭 줄이기: 레벨은 ◀▶ 단추만(레벨 표시는 Task명 앞 배지), 날짜 칸의 요일 글자 대신 토·일은 글자색, 행 단추는 아이콘(⚡ ↳ ＋ ▲ ▼ ×)
     → 1440px 화면에서 가로 스크롤 없이 표시
2. 상태 칩 필터: 요구사항 · VOC · 산출물 · 회의 Action Item 에 WBS 와 같은 상태별 건수 칩 (누르면 그 상태만 표시)
   - VOC · 산출물 · Action Item 은 '지연'(목표일/계획 제출일 지남 + 미완료) 칩 포함
3. 로그인 화면 [🔄 비밀번호 초기화] (테스트 버전): 사번만 입력하면 별도 인증 없이 1234 로 초기화, 다음 로그인 때 변경 필수
   - app.ini [security] self_password_reset=0 으로 끌 수 있음 — 운영 환경에서는 반드시 끄세요 (누구나 다른 사람 비밀번호를 초기화할 수 있음)
4. 단계별 진척 > [2] SDLC 단계별 종합 공정 매트릭스: 단계 머리글이 남색으로 고정되던 것을 테마 색으로 / [3] 개선과제형 표의 머리글과 칸이 어긋나던 것 수정(분야 칸 추가)
5. 공지사항 게시판 · 개선단계 기준정보 제목 옆의 옛 버전 표시(ver1.0.4) 삭제
6. 홈 스타일 단추(브리핑 · 워크벤치 · 내 할 일)를 머리줄 오른쪽 끝에 고정 — 안내 문구 · 건수가 바뀌어도 단추가 움직이지 않음
7. Electric · Navy 테마에서 머리글 기준일 옆 요일이 배경색과 같아 안 보이던 것 수정
8. 소통 채널 단추 · 공지 제목 · 주간보고 미리보기 등에 남아 있던 고정 남색 글자를 테마 색으로

■ [v3.0.1] — 로그인 화면 프로젝트 선택 표시 보완
1. 화면 높이가 낮은 PC(노트북 등)에서 로그인 상자의 위·아래(프로젝트 선택, 등록 링크)가 잘리던 문제 → 로그인 화면을 스크롤해서 볼 수 있게 함
2. DB 서버가 화면 파일(index.html · js · css)을 보낼 때 "매번 확인(no-cache)" 지시 → 업그레이드 후 브라우저 캐시의 이전 로그인 화면이 보이지 않음
3. 권한 메뉴(기준정보 · 시스템 설정) 재인증 화면에도 지금 프로젝트를 표시 (바꿀 수 없음)

■ [v3.0.0] — Neo 단일 화면 · 프로젝트별 사용자 · 로그인 시 프로젝트 선택 · 프로젝트별 소통 채널 · 진척률 0~100
1. 화면은 Neo 하나로 통합 — Standard(클래식) 화면과 화면 방식 선택(사용자 메뉴, app.ini [ui] default_ui / allow_ui_switch) 제거
2. 사용자 정보를 프로젝트별로 관리
   - 계정(사번 · 이름 · 비밀번호)은 사람마다 하나, 역할 · 담당 서브시스템 · 부서는 프로젝트마다 따로 (같은 비밀번호로 여러 프로젝트 사용)
   - [기준정보 > 사용자 정보]에는 지금 프로젝트의 사용자와 시스템관리자만 표시
   - [📥 다른 프로젝트에서 복사] (시스템관리자): 다른 프로젝트의 사용자를 골라 역할 · 담당 · 부서 그대로 복사, 이미 있는 사용자는 건너뜀
   - 사용자 삭제 = 이 프로젝트에서 빼기 (다른 프로젝트 참여는 유지, 어느 프로젝트에도 없으면 계정도 삭제)
   - 시스템관리자는 모든 프로젝트 공통, 시스템관리자 권한 부여 · 해제와 관리자 계정 삭제는 시스템관리자만
3. 로그인 화면에서 프로젝트 선택
   - 시스템관리자: 프로젝트를 고르지 않아도 로그인 가능, 로그인 뒤 머리글에서 프로젝트 전환 가능
   - PM 이하 사용자: 프로젝트를 반드시 골라야 하며, 그 프로젝트의 사용자가 아니면 로그인 거부
     로그인 뒤에는 그 프로젝트만 조회 (머리글 프로젝트 선택 숨김, DB 서버도 다른 프로젝트 요청을 거부)
   - 프로젝트 만들기 · 이름 변경 · 보관 · 삭제는 시스템관리자만 (이전에는 PM 도 가능)
4. 소통 채널을 프로젝트별로 관리 — 새 프로젝트는 '전체' + 그 프로젝트의 서브시스템으로 시작
5. 계획 · 실적 진척률은 0 ~ 100 만 입력 (마이너스 · 100 초과는 경고 후 원래 값 유지, 가중치는 0 이상)
   - WBS 표 · 상세 패널 · 엑셀 올리기 모두 적용, DB 서버도 저장 때 0 ~ 100 으로 보정
6. 이전 데이터 자동 이관 (한 번만): 기존 사용자는 이전에 들어갈 수 있던 프로젝트(참여자 제한 프로젝트는 참여자만)의 사용자가 됨
   — 프로젝트별 역할을 지정해 두었으면 그 역할, 아니면 이전 기본 역할 사용
   — 필요 없는 프로젝트에서는 [기준정보 > 사용자 정보]에서 빼면 됨

■ [v2.4.0] — 홈 스타일 3가지 재정리 · 사용자별 내 할 일 · Neo 기본 화면 · Standard(클래식) 종료 예고
1. 홈 스타일 3가지 (홈 위쪽 단추로 바꾸고, 고른 홈은 사용자마다 기억 / 역할별 기본값은 [시스템 설정 > 화면·테마])

   - 🧰 워크벤치 (구 하이브리드 스마트 포털): 실무 담당자 — 내 담당 서브시스템의 진행 중 과업과 원클릭 실적 반영, 요약, 공지·소통

■ [ver1.0.10 개선 내역] — 보안 강화 · 여러 프로젝트 · Windows 패키지
1. 비밀번호 보안
   - 서버 저장: 브라우저 1차 해시(SHA-256)를 사용자별 솔트 + PBKDF2-SHA256(600,000회)으로 다시 해시하여 저장
     (형식 pbkdf2_sha256$반복$솔트$해시, 비교는 상수 시간). v1.0.9 이하 비밀번호는 서버 첫 기동 때 자동 전환
   - 초기 비밀번호(1234)·관리자 지정 임시 비밀번호로 로그인 시 비밀번호 변경 필수 (변경 전에는 서버 데이터 API 차단)
   - 새 비밀번호 규칙: 8자 이상, 영문+숫자 포함, 초기 비밀번호·쉬운 비밀번호 금지
   - 일반 사용자는 사용자 데이터 저장으로 비밀번호를 바꿀 수 없음 (비밀번호 변경 API 로만 변경)
   - 시스템관리자 권한은 시스템관리자만 부여 가능
2. 통신 암호화 (HTTPS)
   - make_cert.bat (tools/make_cert.py): OpenSSL 없이 사내 CA + 서버 인증서(RSA 2048, SHA-256, 397일) 생성
     → certs\ca.crt 를 접속 PC 의 [신뢰할 수 있는 루트 인증 기관]에 설치 (그룹 정책 배포 가능)
   - run_server.bat: certs\server.crt + certs\server.key 가 있으면 자동으로 HTTPS(TLS 1.2 이상) 기동
     (직접 실행: python wbs_db_server.py --cert certs/server.crt --key certs/server.key)
   - HTTPS 사용 시 HSTS 헤더 전송, 인증서·개인키 파일은 웹으로 내려받을 수 없게 차단, 배포 zip 에서 제외
3. 스크립트 실행 제한 (콘텐츠 보안 정책, CSP)
   - 화면의 인라인 스크립트(onclick 등 478개)를 모두 data-click 등 선언형 속성 + js/ui-events.js 로 전환
   - 서버는 index.html 에 Content-Security-Policy: script-src 'self' (인라인·외부 스크립트 실행 차단) 전송
   - 다른 사이트(Origin)에서의 API 호출 차단 (CORS 는 같은 서버 주소만 허용, --allow-origin 으로 추가 가능)

■ [대용량 데이터(수천 행 이상) 대응 방안 — 검토 결과]
 현재 구조: 데이터 변경 시 rebuildAll() 이 재계산 후 WBS·간트·대시보드 등 모든 화면을 다시 그림.
 측정 기준(현 샘플 232행)은 문제 없으나, 5,000행 이상에서는 입력 1건마다 수백 ms~수 초 지연이 예상됨.
 권장 단계별 대안:
  ① [1단계 · 효과 큼 · 적용 쉬움] 보이는 탭만 다시 그리기
     - rebuildAll 에서 재계산은 유지하되 렌더링은 현재 활성 탭만 수행, 나머지 탭은 "갱신 필요" 표시 후 탭 진입 시 그림
  ② [1단계] WBS 표 가상 스크롤 (virtual scrolling)
     - 화면에 보이는 30~50행만 DOM 으로 만들고 스크롤 위치에 따라 교체 → 행 수와 무관하게 일정한 속도
     - 간트차트도 같은 방식(목록·차트가 이미 단일 스크롤 영역이라 적용 용이)
  ③ [2단계] 증분 재계산
     - 진척 롤업을 변경된 서브시스템(파티션)만 다시 계산 (현재 저장 계층의 파티션 구조 재사용)
     - 변경 감지(diff)도 변경된 파티션만 비교하도록 dirty 플래그 도입
  ④ [2단계] 입력 디바운스 · 배치 처리: 연속 입력은 300ms 묶어서 1회 재계산
  ⑤ [3단계 · 데이터 수만 행] 서버 측 페이징 / 서브시스템 단위 지연 로딩
     - 로그인 시 담당 서브시스템만 불러오고, 통합 화면(대시보드)은 서버가 집계한 요약값 사용
     - 계산 로직을 Web Worker 로 분리하여 화면 멈춤 방지
 권장 순서: ①+② (체감 효과 대부분) → 데이터 증가 추이에 따라 ③④ → 필요 시 ⑤
